# 「표류자」 기획부터 대본·장면표까지 — 실제로 밟은 절차

EP.1을 만들며 실제로 거친 순서를 그대로 적었다. 다음 회차는 이 순서를 따라가되, 이미 끝난 단계(0~4)는 건너뛰고 5단계부터 시작한다. 단계마다 **산출물**과 **나중에 리뷰에서 걸린 점**을 함께 적었다. 걸린 점은 처음부터 지키면 재작업이 줄어든다.

```
0 채널 결정 → 1 시즌 설계 → 2 바이블 → 3 엔진 사양 확인 → 4 캐릭터
        → 5 회차 대본 → 6 장면표·프롬프트 → 7 오버레이·도면 → 8 메타데이터
        → 9 린트·리허설 → 10 리뷰 3겹 → 11 (다음) 레퍼런스 → TTS → 영상 생성
```

## 0. 채널 결정 (1회)
1. **리서치**: Opus 렌즈 4개(시장, 컨셉, 정책·사업, 제작)를 병렬로 돌리고, Fable 비평가가 종합했다.
   - 시장: 벤치마크 채널('문명')의 업로드 날짜·조회·댓글을 직접 파싱했다. 클론 채널 목록을 만들고, 댓글 반응을 유형별로 분류했다.
   - 컨셉: 후보 6개를 가중합으로 채점했다(수요, 차별화, 정책 위험, 제작 난도, 운영자 강점).
2. **결론**: 「표류자」 K1(4.10점)으로 정했다. 8주 파일럿, 상한은 $400·60시간.
- 산출물: `scratchpad/newch/*.md` 리서치 원문, 판정표 → 바이블에 흡수.

## 1. 시즌 설계 (시즌당 1회)
1. **실제 기록에서 루트를 정한다.** 하멜 일행 기록을 따라 제주 → 해남 → 한양 → 강진 → 여수로 잡았다. 시즌 안에서는 연속이고, 시대는 시즌 단위로만 바꾼다.
2. **기술 트리를 짠다.** 회차마다 기술 1개와 원리 1개를 붙이고, 같은 기술은 두 번 쓰지 않는다(DAG). 시즌1은 물 → 불 → 소금 → 신발 → 우비 → 필담 → 온돌 → 등잔 → 떼배 → 봇짐이다.
3. **결말 유형을 배분한다.** 10화 기준 성공 6 / 부분 3 / 실패 1이고, 같은 유형이 2회 연속 오지 않게 한다. YouTube 비진정성 정책의 "same situation … same outcome" 대응이다.
4. **떡밥 장부를 만든다.** 심는 회차와 회수 회차를 정한다. 미회수 떡밥은 3개를 넘기지 않는다.
- 산출물: `bible/series_bible.yaml`의 `season1_episodes`, `foreshadow_registry`, `route_table`.

## 2. 바이블 (시즌당 1회)
1. **세계 규칙 R1~R6을 정한다.**
   - 그 시대 재료만 쓴다.
   - 큰 역사는 바뀌지 않는다.
   - 기술을 기록할 때마다 돌아가는 단서가 쌓인다.
   - 전투·사상자는 화면 밖에서 처리한다.
   - 실존 인물은 실루엣으로만 보여 준다.
   - 동물은 위기 소재로 쓰지 않는다.
2. **연재 대본 12슬롯을 정한다.** STATE / NEED / HAVE / GATHER / FAIL / PRINCIPLE / BUILD / TEST / COST / UNLOCK / NEXT / TAG이고, 슬롯마다 규칙이 붙는다.
3. **금지 목록을 정한다.**
   - 보디캠·CCTV·뉴스 포맷('순찰 24시' 사건)
   - 실존 상표
   - 아동 소구 단어(아이·어린이·동화·귀여·kids·cute)
4. **회차 상태 원장(`bible/ledger.json`)을 만든다.** 회차가 끝날 때의 인벤토리·위치·부상·결말 유형을 적는다. 다음 회 HAVE 슬롯은 이 원장의 인벤토리만 쓸 수 있다.

## 3. 영상 엔진 사양 확인 (엔진이 바뀔 때마다)
1. **공식 문서를 직접 읽는다.** 재판매처 문서는 쓰지 않는다. docs.x.ai의 video generation, reference-to-video, extension, image edits, pricing, prompting guide를 읽었다.
2. **확정한 사양**
   - `image`로 첫 프레임 고정, `reference_images` 최대 14장
   - 레퍼런스를 쓰면 720p 상한
   - 1~15초
   - `generate_audio:false`
   - 편집 입력 최대 5장
   - 1.5 모델 $0.08/초
3. **이 사양으로 연결 방식을 설계했다**(운영자 요구: 앞 영상 마지막 이미지 → 뒤 영상이 행동을 이어받음).
   - C 이어가기 / A 앵글 컷 / T 시간 점프 / K 키프레임 / F 정지
   - C는 연속 1번까지만 쓴다. 드리프트가 쌓이기 때문이다.
   - 매 요청에 레퍼런스를 동봉한다.
- 걸린 점: 재판매처 단가($0.14/초)를 공식가($0.08/초)로 착각하고 있었다. 공식 가격표를 먼저 본다.

## 4. 캐릭터 (시리즈당 1회)
1. **디자인 결정 이유를 먼저 적고 그다음 그린다.**
   - 문명과 겹치지 않을 것(검은 동그란 머리 금지)
   - AI 영상에서 얼굴이 무너지는 실패를 피할 것(얼굴 없는 달걀형 머리)
   - 9:16 작은 화면에서 0.5초 안에 식별될 것(검은 현무암 위 주황 조끼 + 주황 고양이)
   - 아동용 재분류를 피할 것(성인 체형, 무표정, 저채도)
2. **디자인 기준 시트를 만든다**(`characters/model_sheet.svg`): 비율, 색 HEX, 식별점에 번호를 매긴다.
3. **레퍼런스 프롬프트를 쓴다**(`characters/refs.json`, xAI 이미지 가이드 순서).
   - 순서: 피사체 한 문장 → 세부 → 빛 → 색 → 구도. 4~6문장이고, 부정 목록은 쓰지 않는다.
   - 파생본(측면·후면·자세)은 확정 이미지를 편집해서 만든다. 그래야 정체성이 유지된다.
4. **레퍼런스 선택 기준 체크리스트를 쓴다**(`characters/CHARACTERS.md` 3절).
- 걸린 점: 처음에 '머리 = 키의 1/4'로 정했는데, 이는 4등신, 곧 유아·SD 비율이다. '성인 체형'이라는 목표와 반대여서 6등신으로 바꿨다. **비율은 등신으로 환산해서 확인한다.**

## 5. 회차 대본 (매 회차) ← 다음 회차는 여기서 시작
1. **회차 사양을 시즌 표에서 가져온다**: 만드는 것, 원리, 결말 유형, 다음 회 연결고리. EP.1은 대나무 물통 / 민물-바닷물 밀도 차·해안 용천수 / 성공 / 쇠못(→EP.2 불)이다.
2. **사실 주장을 먼저 뽑아 검증한다**(`ep01/factcheck.md`). 주장마다 출처 2개를 찾고, 못 찾으면 문장을 약하게 바꾼다.
   - "사흘을 버틴다" → "보통 사흘 안팎"(의학적으로 정확한 수치가 없음)
   - "2.5퍼센트 가볍다" → "약 2.5퍼센트"(1.000 대 1.025는 정확히 2.44%)
   - "이 섬 사람들은 용천수라 불렀다" → "오늘날 이런 물을 용천수라 부른다"('용천수'는 현대 용어라 시대착오)
   - "살아남은 건 둘뿐" → "이 바위 해안에 닿은 건 둘뿐"(실제 하멜 생존자 36명과 충돌하지 않게)
   - "빗물이 그대로 스며드는" → "빗물이 잘 스며드는"(함양률은 약 40~45%이므로 '전부'가 아님)
3. **12슬롯에 맞춰 내레이션을 쓴다**(`ep01/shots.json`의 `narration`). 규칙:
   - 3인칭, 성인 다큐 톤. 주인공은 말하지 않는다.
   - 첫 문장은 2.6초 안에 끝낸다. NEED에는 숫자 1개.
   - PRINCIPLE은 원리 1개, 정밀 숫자 1~2개, 느린 속도(4.6음절/초).
   - 과학 비중은 15~20%.
   - 음성 CTA 없음. 클리프행어로 끝낸다.
4. **읽기용 표기를 따로 둔다.** 숫자를 한글로 풀어 쓴다: `"1653년"` → `tts: "천육백오십삼 년"`, `2.5퍼센트` → `이 점 오 퍼센트`.
5. **음절 수로 타이밍을 계산한다**(`tools/grok_chain.py render`).
   - 기본 5.0음절/초, PRINCIPLE 4.6음절/초.
   - 쉼표 0.2초, 줄 사이 0.35초, 슬롯이 바뀌면 +0.25초.
   - 목표 총 길이는 90~120초(EP.1은 109초). 줄마다 3.5~5.6음절/초 안에 들어야 린트를 통과한다.
6. **원장과 대조한다.** HAVE에서 보여 주는 인벤토리 = 직전 회 원장 인벤토리여야 하고, 획득 카운터 = 이번 회 원장 개수여야 한다. 결말 유형이 직전 회와 같으면 안 된다. `check`가 자동으로 검사한다.
7. **만드는 과정의 물리를 검산한다.** EP.1 리뷰에서 걸린 것:
   - 6cm 대나무에 4초 만에 깊은 홈을 한 바퀴 파는 것은 불가능하다 → '몇 분 뒤, 홈이 거의 완성된 상태'에서 시작한다.
   - 평평한 바위 위에서 누르면 대나무가 꺾이지 않는다 → 홈을 바위 모서리에 걸치고 튀어나온 쪽을 누른다.
   - 마디 '바로 아래'를 잘라야 마디가 바닥이 된다.
   - 마개는 2초 만에 깎을 수 없다 → 거의 다 깎은 마개에서 시작한다.
   - 물때 변화에는 1시간 이상 걸린다 → 시간 점프(T)로 처리한다.

## 6. 장면표·영상 프롬프트 (매 회차)
1. **샷을 내레이션 줄에 묶는다.** 샷 시작을 절대 초가 아니라 "N03 시작 −0.1초" 같은 줄 앵커로 정한다. TTS를 녹음하고 나서 `render`를 다시 돌리면 모든 샷 길이가 실측에 맞춰 바뀐다.
2. **샷마다 연결 방식(C/A/T/K/F)과 출발 샷(`from`)을 정한다.** 지형이 필요하면 참고 프레임(`context`)을 붙인다.
   - 참고 프레임을 붙일 때는 "지형만 가져오고 인물·고양이는 한 번만"이라고 명시한다.
   - 이미 소모된 소품(잘라 쓴 대나무 등)이 보이는 프레임을 참고하지 않는다.
3. **영상 프롬프트를 쓴다**: 시작 프레임 → **새로 더할 행동만** → 카메라 1개 → "It ends with …" 끝 상태.
   - 실행기가 자동으로 붙이는 것:
     - 정체성 문장(레퍼런스별)
     - 빛 프리셋
     - **"약 N초에 끝 상태에 도달한 뒤 정지"**(N = 아웃 포인트 −0.3초)
   - 샷 길이 대비 동작 수: 3초 컷에 동작 2~3개까지. 넘으면 나누거나 시간 점프로 처리한다.
4. **편집 프롬프트(A/T/K)를 쓴다**: 바꿀 것(카메라·시간·자세)을 먼저 쓰고, 유지할 것은 한 문장만 쓴다(xAI 가이드). 입력 이미지는 5장 이하.
5. **끝 상태(`end_state`)를 한국어로 적는다.** 다음 샷의 출발점이므로 위치·소품·물때·젖음 상태까지 쓴다.
6. **얼굴 없는 머리 규칙**(리뷰에서 반복해서 걸린 것)
   - 시선 동사(looking, watching, gazing)는 쓰지 않는다 → "head turned toward …"
   - 입 위치를 지목하지 않는다("lower front of its head", "as if drinking" 금지) → "up close beneath its blank head"
   - 정면 장시간 노출은 피한다. 고개를 숙이거나 옆모습으로 잡는다.
   - 손만 나오는 샷에는 머리 정체성 문장 대신 "head stays out of frame"을 쓴다(샷별 `identity`).
   - 부정형 명사("no one else")도 쓰지 않는다. 그 대상을 불러낸다 → "the shoreline is empty in both directions"
7. **동물 규칙**: 파도·위험이 오기 **전에** 고양이가 먼저 피한다. 젖은 털 같은 상태도 앞뒤 샷과 이어지게 쓴다.

## 7. 오버레이·도면 (매 회차)
1. **회차마다 같은 위치에 들어가는 고정 요소**(`ep01/overlays.json`)
   - 첫 2초 'AI 창작 시리즈 · 1653'(좌하단)
   - 상태 자막 'D+n · 날짜 · 장소'
   - 상시 'EP.n' 버그
   - HAVE 인벤토리
   - 획득 카드(누적 개수)
   - 해 질 녘 지도(OSM 표기)
   - 엔드카드
2. **원리 도면**(`ep01/diagram_*.svg`): 레이어를 나눠 내레이션 줄에 맞춰 0.7~1.2초씩 순서대로 그린다. 완성 상태를 한 번에 띄우지 않는다.
3. **모든 오버레이의 시각도 줄 앵커로 정한다.** 끝 시각은 다음 컷 경계에 맞춘다(넘어가면 다음 샷 위에 남는다).
4. 위험 기술 회차는 경고 오버레이가 의무다. 구체 수치까지 쓴다("1분 이상 팔팔 끓여").
5. 1080×1920 세이프존 안에 둔다(위 220, 아래 484, 왼쪽 60, 오른쪽 140px). 동시에 뜨는 글자 덩어리 수를 센다.

## 10. 리뷰 3겹
