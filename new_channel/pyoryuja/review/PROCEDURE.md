# 페르소나 리뷰 절차 — 「신비한 건축사전」 제작자 × 「문명」 제작자

회차를 영상으로 만들기 **전에**(대본·장면표·오버레이 단계) 두 외부 제작자의 눈으로 심사한다. 목적은 "우리 기준"이 아니라 "이미 성공한 두 문법"으로 회차를 두드려 보는 것이다. 결과는 바이블과 충돌하는 제안을 걸러 **지금 반영 / 다음 회차 반영 / 기각**으로 나눈다.

## 언제 돌리나
- 매 회차 `check` 통과 뒤, 레퍼런스·영상 생성 전. (대본·오버레이 수정은 비용 0, 영상 생성 뒤 수정은 비용이 든다.)
- 시즌 기획 때 EP.0 아웃라인과 시즌 표에도 한 번.

## 입력
| 파일 | 용도 |
|---|---|
| `ep{n}/shots.json` | 원본. 내레이션·샷·프롬프트·끝 상태 |
| `ep{n}/script.md`, `shotlist.md` | 렌더된 대본·장면표(타임코드) |
| `ep{n}/overlays.json`, `diagram_*.svg`, `*_preview.jpg` | 오버레이·도면 |
| `ep{n}/metadata.md` | 제목·설명·고정 댓글·커버 |
| `ep{n}/build/timeline.json` | 줄·샷 시각 |
| `bible/series_bible.yaml`, `bible/ledger.json` | 바이블(충돌 판정 기준) |
| `review/personas/*.md` | 페르소나 카드(사실·문법·체크리스트·편향) |

## 단계
1. **페르소나 리뷰 (병렬 6)** — 두 페르소나 × 3렌즈. 각 리뷰어는 자기 페르소나 카드만 읽고 그 사람으로서 회차를 본다. 렌즈:
   - 건축사전: ① 오버레이·도면 ② 영상 구조·페이싱 ③ 대사·제목
   - 문명: ① 연재 장치·캐릭터 ② 대본·비유·과학 비중 ③ 운영·오버레이 시스템
   - 산출: 지적 사항(위치·문제·증거·구체 대안), 6개 항목 1~5점, "내가 이 회차를 만든다면 가장 먼저 바꿀 것 3개".
2. **교차 심문 (병렬 2)** — 각 페르소나가 상대 페르소나의 상위 제안을 읽고 "그렇게 바꾸면 내 기준에서 무엇이 깨지는가"를 말한다. 두 문법이 충돌하는 지점을 드러내기 위한 단계다.
3. **판정 (1, Fable)** — 바이블·가드레일·비용을 기준으로 모든 제안을 분류한다.
   - **A 지금 반영**: 대본·오버레이·제목·메타데이터처럼 영상 생성 전에 비용 0으로 바꿀 수 있고 바이블과 충돌하지 않는 것
   - **B 다음 회차·시리즈 규칙**: 슬롯 템플릿·바이블·운영 규칙을 바꿔야 하는 것
   - **C 기각**: 바이블·정책과 충돌, 근거 부족, 페르소나 편향(카드 5~6절)
   - 두 페르소나가 충돌한 지점은 "우리 선택"과 이유를 적는다.
4. **반영** — A는 `shots.json`·`overlays.json`·`metadata.md`에 적용하고 `check`·`render`를 다시 돌린다. B는 `bible/`과 `README.md`에 적고 다음 회차 대본에 적용한다. 결과 보고서는 `review/ep{n}/persona_review.md`에 남긴다.

## 실행
```
# 저장된 워크플로우 (.claude/workflows/pyoryuja-persona-review.js)
Workflow({ name: "pyoryuja-persona-review", args: { episode: "ep01" } })
```
리뷰 에이전트는 Opus, 판정은 Fable로 고정돼 있다(운영자 설정). 결과 JSON을 받으면 아래 보고서 형식으로 정리한다.

## 보고서 형식 (`review/ep{n}/persona_review.md`)
1. 점수표(페르소나 × 6항목)와 "가장 먼저 바꿀 것 3개" 두 줄
2. A 지금 반영 — 항목별 위치·변경 전/후·이유
3. B 다음 회차 — 규칙으로 적을 문장
4. C 기각 — 한 줄 이유
5. 두 문법의 충돌과 우리 선택
6. 반영 결과(check/render 로그 요약)

## 합격선
- A 항목이 0개가 될 때까지 반복하지 않는다. **1회 반영 후 재심사는 하지 않는다**(페르소나 리뷰는 품질 상한을 올리는 도구이지 게이트가 아니다). 게이트는 `check`(린트)와 사실 확인 시트다.
- 두 페르소나 평균 점수가 6항목 중 4개 이상에서 3.5 미만이면 회차 구조를 다시 짠다.
